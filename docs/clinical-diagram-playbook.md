# 臨床流程與概念圖製作手冊

日期：2026-11-16。適用於本專案之臨床複習路徑、概念圖、可編輯定義、SVG、文字對照及網站呈現。依 [AGENTS.md 第8節](../AGENTS.md)，先完成臨床路徑與案例核對，再處理排版及工程。圖的用途、來源版本與審閱狀態在圖外集中呈現；影響決策的條件放在相關建議旁。

## 2. 固定的八步製作流程

### 第一步：定義臨床旅程及種子情境

寫清「讀者帶著什麼問題進來，看完應能走到哪裡」，確認族群、照護場域、來源版本及既有疾病頁。列典型、重症／警訊、初始治療無效、關鍵資料未取得等對比情境；先寫問題，隨來源閱讀補預期答案。

疾病複習圖預設檢視：**辨認／鑑別與驗證→診斷→嚴重度／分型→具體處置→反應重評→升階、減階、維持或追蹤。** 依疾病及任務組織，不要求每階段各一框。指定檢驗或診斷準則的任務可較窄；疾病複習須接上處置與後續。

產物：臨床問題、預期終點、種子情境及其核心問題。

### 第二步：從原始材料建立臨床主幹

開啟原圖、相鄰正文、表格與註腳，一起讀互相銜接的圖。標出入口、關鍵發現、改變去向的條件、處置包、重評時間／指標、成功與失敗去向。有原圖時先保留其臨床架構；只有正文或表格時，整理成狀態、條件、行動，再按資料依賴、處置先後及反應連接。

以已提供來源補足嚴重度、處置與藥物資料。缺口記在製作紀錄；外部補查依AGENTS第9節及既有授權。引用、版本核對及閱讀進度留製作紀錄，主線呈現讀者此時需要的臨床工作。

產物：逐項有來源定位的主幹與內容缺口。

### 第三步：建立狀態—行動—回饋表

使用[製作紀錄範本](../04_templates/clinical-diagram.md)，逐列填寫：

| 臨床狀態／問題 | 已有與需取得的資料 | 改變下一步的條件 | 具體行動／具名選項 | 何時、用什麼重評 | 各結果後續 | 來源定位 |
| --- | --- | --- | --- | --- | --- | --- |

保留AND／OR、全部／至少幾項、數值、不等號、單位、時間、排除條件、互斥或並行關係。未知與陰性分開；準則未滿足與排除疾病分開，主準則與次要線索各保留其作用。區分來源明述、編輯連接與未給定資訊，推薦強度及可選性沿用來源。

用藥行動依任務列藥名、選用因素、起始／目標／上限、途徑、頻率、調整／停換、安全條件及監測，可用治療包或旁表承載。腎肝、代謝與交互作用逐藥保留指標、單位、方向及適用範圍。重評時程與結果後續接到所屬處置；來源未提供的操作資訊明列缺口。

產物：每個關鍵分支的行動、時間、去向及來源。

### 第四步：先走完整文字路徑

逐一代入種子情境：現在看什麼／查什麼，什麼結果改變判斷，做什麼，何時看反應，改善、無效或惡化各去哪裡。急迫處置保留優先去向；並行工作包及可並用治療保留並行關係。

疾病複習在診斷後接嚴重度／分型與處置。子圖的接點寫明下一個臨床任務，且子圖已有實際內容。「請看本文」「依本篇處理」不能代替主要下一步。

產物：僅沿主圖與具名子圖即可回答主要臨床問題的文字路徑。

### 第五步：刪除無作用節點

逐框做刪除測試：**移除後，讀者需要的資料、條件、行動、時間與去向是否完全相同？** 相同就合併或刪除。每框須在取得資料、形成臨床判斷、比較選項、執行處置或檢視結果。

- 出線已標具體條件時，可直接由前一工作包分支，不再加只重述條件的「判斷目前狀態」框。
- 同時核對且無先後依賴的準則合清單；一起執行的動作合處置包。會改變處置的分類各接相應行動。
- 「6–12週改善？」同時承載時點與反應判斷，可以保留；框形依閱讀需要選擇。
- 未知在改變當下行動時另開路，寫明等待哪項資料、期間做什麼、取得後回哪裡；其餘以工作包內的核對項表達。工具不得強迫每個判斷都加獨立未知出口。
- 不機械追求最少節點。適量局部重複可讓讀者沿單一路徑讀完。

產物：每框有臨床工作，出線條件有清楚判斷對象。

### 第六步：改成直接醫學短句

對附加提醒逐句問：**刪掉後會改變此處的判斷、行動、劑量、時點或去向嗎？** 不會就刪除；會則將必要條件直接寫入建議。使用「一線加用藥物」「目標量」「短期降低自殺意念」等準確表述，取代一串假設誤用或未被提出的反駁。用途、版本、審閱狀態及通用說明在圖外集中一次。

關鍵條件、主要動作、選用限制與分歧鄰接建議；機轉、理由與較長證據討論放旁註、附表或正文。精簡前後須保留適用範圍、推薦強度、劑量性質與結果終點。

產物：保留臨床選擇所需資訊的短句及刪改紀錄。

### 第七步：依臨床任務選圖

| 臨床問題 | 合適的圖型與組織 |
| --- | --- |
| 疾病從辨認到後續如何銜接？ | 按階段或照護場域分區的路徑，主線接處置與反應 |
| 急性嚴重度如何改變處置？ | 並排分級，各接治療與升階出口 |
| 慢性治療如何調整？ | 階梯／軌道與重評迴圈 |
| 一套準則或共同資料包有哪些項目？ | 分組清單，完整保留組合條件，再接臨床行動 |
| 鑑別、藥物及共病選項如何比較？ | 對照表，關鍵差異接回主線；需要時用具名子圖 |
| 機轉與概念有哪些關係？ | 概念／心智圖，連線寫關係；判斷與處置另用條件路徑 |

以一個臨床任務控制框內容；長段落先拆旁註或有內容的子圖，不把全文套成同款卡片。主圖直接顯示關鍵條件、數值與動作。密度檢查先刪無作用框與重複句，再分區／拆圖、調寬與留白；字級維持可讀。

產物：可沿單一路徑追蹤各分支的草圖。

### 第八步：先驗臨床複習，再驗圖面與工程

讓審查者只看圖，以先寫的情境回答下一步資料、行動、重評時間／指標與各結果去向，再與來源及預期答案比對。以相同案例核對精簡前後的條件、行動、時間與去向。依相關規則補走缺資料、陰性與未知並存、數值／時間邊界、並行條件、例外、換藥方向及回饋迴圈；教學情境標明虛構。

臨床路徑成立後才做實際渲染、碰撞、字級、箭頭、文字版、裝置、引用與建置檢查。同步受影響正文、答案、表格、資產、index及log，保存單一可編輯定義與圖文對照。

產物：來源、路徑、文字精簡、圖面／裝置及工程分開的驗收紀錄。

## 3. 視覺語法與密度檢查

- **主軸向下。** 正常閱讀從起點往下；例外分到側邊，回饋線帶文字且外繞。避免箭頭穿過卡片，轉折不以動畫暗示臨床順序。
- **資訊層次。** 明確標題、臨床短句／分組項目與可讀來源；卡片可加小型用途標籤。共同準則保留完整關鍵條件，標題說明實際判斷或動作。
- **少量顏色。** 藍色為評估／一般行動，青色表達後續與結果，琥珀色配「未確認／補資料」，紅色配「安全／優先評估」。色彩不另建立風險分數，也不能是唯一識別。
- **箭頭語意。** 實線表示閱讀或有條件去向；標「可考量」的選項用選項線；回饋線明寫補資料或重評。圖例與文字同時說明，虛線不是低證據等級。
- **閱讀尺寸。** 臨床卡片正文18px、標題22px、來源／角色14px；分支標籤至少16px。以原始尺寸閱讀，提供捲動、縮放及開啟完整圖。整圖縮圖只作概覽，不算閱讀檢查通過。
- **密度控制。** 逐框檢查是否只有一個臨床任務或一組共同準則；讀者需不斷左右找線、回線難追或同框混入多階段工作時，先重新分區或拆具名子圖。字數及框數依內容決定。
- **中文與數值。** 中文依可用寬度換行；藥名、數字＋單位、比較符號附近逐項檢查。不能裁掉否定詞、註腳、百分比基準或「目標量」等劑量性質。
- **留白與對齊。** 等距內邊、同層卡片對齊，分支標籤有白底且不蓋住線路。節點大小隨內容調整，不能用同大空框或巨型菱形填滿版面。

## 4. 驗收需留下的證據

| 層次 | 必查項目 | 完成依據 |
| --- | --- | --- |
| 來源 | 版本、族群、所有數值／條件、表圖註腳、建議語氣、衝突 | 定位及來源審查紀錄 |
| 臨床路徑 | 診斷後銜接、具體行動、時點／指標、反應後續、未知與並行條件 | 先從來源寫預期答案，再只看圖完成虛構教學情境 |
| 精簡 | 無作用節點、重複句、長段落、旁註／主線分配 | 刪除測試及精簡前後同一組案例的答案一致 |
| 圖形 | 完整字串、無遮擋／越界、可追箭頭、層級與留白、原尺寸閱讀 | 實際 SVG 渲染檢視，非僅 XML 合法 |
| 工程 | 安全轉義、定義驗證、圖文一致、雜湊、確定性、舊流程相容、公開邊界 | 適用測試、flow驗證、建置與lint |
| 介面 | 電腦／平板／手機、鍵盤、縮放、文字模式、無JS、列印 | 實際操作；無工具時明示未驗證，靜態PNG不代替瀏覽器驗收 |

每項記實際完成範圍及待補項目；來源與衝突狀態依AGENTS第6、11節。既有一輪驗收保存於 [redesign audit](clinical-flow-redesign-audit.md)，新修改另記對應版本。

## 附錄A：工程參考與現有實作

2026-11-15核對的排版工具如下；圖型先由臨床內容決定，需要新呈現方式時再實作及驗證。

| 工具參考 | 借用的做法 | 現有採用範圍 |
| --- | --- | --- |
| [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)、[elkjs](https://github.com/kieler/elkjs) | 分層、不同節點尺寸、正交路由及線標籤 | 臨床卡片於建置時使用鎖定的elkjs 0.12.1，產圖後實際檢視 |
| [React Flow自訂節點](https://reactflow.dev/learn/customization/custom-nodes)、[排版](https://reactflow.dev/learn/layouting/layouting) | 按資訊用途設節點，排版與互動分開 | 參考於自製SVG與既有縮放／定位；未引入React Flow執行期 |
| [D2 containers](https://d2lang.com/tour/containers/) | 用具名容器表達所屬 | 用於共同清單及子圖分組的設計參考；未安裝D2 |
| [Markmap](https://github.com/markmap/markmap) | Markdown階層轉心智圖 | 用於辨認概念圖的用途；未實作Markmap |
| [Mermaid flowchart](https://mermaid.js.org/syntax/flowchart.html) | 文字定義與分支 | 同一定義匯出Mermaid；既有圖保留Pele 1.13.0 |

`config/flows/<id>.yml` 是單一圖文定義，欄位見 [schema](schema.md)。現有 `presentation: clinical-cards` 使用卡片，省略時保留Pele；`items` 為可見純文字項目，`role` 為視覺用途，`kind` 表達圖結構。卡片可設 `card_width` 320–720；這些是現有呈現規格，不要求所有臨床內容使用同款卡片。

箭頭列 `from`、`to`、`label`，選項或回饋需要時設 `role: option / feedback`。使用unknown節點時，離開它的線須明示補資料／重評並設feedback；terminal表示該圖的終點。未知路徑按臨床行動需要設置。

SVG使用原生向量與文字；定義、排版程式、固定套件及成品雜湊保存於manifest。ELK使用固定非零亂數種子，並以不同啟動時間的新程序核對相同輸入的幾何是否一致；零值會改用隨機種子。公開clone可用核對過的成品建置，重新排版才需安裝Node套件。Mermaid與網站文字版從同一定義產生，保留可見項目；程式檢查不得要求增加沒有臨床工作的框。

```powershell
npm ci --prefix tools/diagrams --ignore-scripts
python scripts/flows.py --build
python scripts/flows.py
python scripts/build_site.py
python scripts/lint.py
python -m unittest discover -s tests -v
```
