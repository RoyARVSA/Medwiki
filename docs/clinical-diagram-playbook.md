# 臨床流程與概念圖製作手冊

日期：2026-11-15。適用於本專案之流程定義、SVG、文字對照及網站呈現。臨床內容依 [AGENTS.md 第8節](../AGENTS.md)；本文件補充如何把已核對的內容畫清楚。它是專案的實作規範，不代表外部機構認證或某引擎的優劣排名。

## 1. 參考專案與採用決定

## 2. 先決定圖要解決什麼

| 問題 | 呈現 | 避免 |
| --- | --- | --- |
| 這個主題有哪些面向、彼此什麼關係？ | 階層／概念圖，連線說明關係 | 把放射分支當診斷或處置順序 |
| 一套診斷要求哪些條件？ | 完整檢核卡＋整合判斷＋資料出口 | 每條準則各畫成無條件的下一步 |
| 哪些結果改變鑑別或驗證？ | 有條件分支＋具名驗證方法 | 「不符合A」直接等於「確診B」 |
| 現在要看什麼、做什麼、何時重評？ | 評估卡→條件→行動／選項→回饋 | 「再評估→最佳化→處理」而無內容 |
| 多種藥物和共病條件如何比較？ | 逐藥操作表，必要時另作子流程 | 症狀、肝腎單一數值直連唯一藥物 |

準則卡上的「符合／不符／未知」是學習時的資訊分類，除非另行實作並驗證，不製作可勾選的病人診斷工具。本站不持久保存個案或學習狀態。

## 3. 從來源到圖形的固定步驟

1. **定義問題。** 寫清族群、版本、起訖、資料範圍與不涵蓋的操作。先查既有疾病頁與流程，避免另建平行結論。
2. **讀原始材料。** 原圖、表、相鄰正文、註腳、例外一併閱讀；使用來源定位，不依摘要或模型記憶填入判斷。
3. **完成決策表。** 使用[製作紀錄骨架](../04_templates/clinical-diagram.md)，逐列填入資料、條件性質、行動、未知、重評及來源。醫學規則和編輯閱讀安排分開。
4. **先走文字路徑。** 用來源先定的案例檢查可否得到具體下一步。沒有依據就記缺口；不為畫菱形而新增分數、週數或門檻。
5. **分組與減少線路。** 同時核對的資訊合卡；只有會改變去向才分支。並行選項不排成必經順序。超出一個閱讀問題時拆成相連子圖，保留同一疾病入口。
6. **輸入 YAML。** 正文、來源清單、版本、節點項目與分支齊全，再建置。主圖直接寫出重要動作／條件，detail 補說明而非藏關鍵答案。
7. **產圖與看圖。** 自動排版後實際渲染，逐個看長中文字、藥名、單位、不等號、分支標籤與回饋線。排版不好先調寬、縮短非關鍵文句或拆圖；不改醫學邏輯迎合引擎。
8. **核對並記錄。** 分開做來源／臨床路徑、視覺、工程與裝置檢查。記實際範圍及未查項目；有重要問題先修正，人工 review 狀態仍維持原規則。
9. **同步建置。** 更新資產紀錄、受影響正文／問答／表格、index/log，執行公開建置。舊快取或雜湊不合不能冒充新成品。

## 4. 視覺語法

- **主軸向下。** 正常閱讀從起點往下；例外分到側邊，回饋線帶文字且外繞。避免箭頭穿過卡片，轉折不以動畫暗示臨床順序。
- **卡片內的層次。** 小型用途標籤→明確標題→短項目→可讀來源。五項準則放一張清單，各項保留完整關鍵條件。標題不要只有「評估」「處置」。
- **少量顏色。** 藍色為評估／一般行動，青色表達後續與結果，琥珀色配「未確認／補資料」，紅色配「安全／優先評估」。色彩不另建立風險分數，也不能是唯一識別。
- **箭頭語意。** 實線表示閱讀或有條件去向；標「可考量」的選項用選項線；回饋線明寫補資料或重評。圖例與文字同時說明，虛線不是低證據等級。
- **閱讀尺寸。** 臨床卡片正文18px、標題22px、來源／角色14px；分支標籤至少16px。以原始尺寸閱讀，提供捲動、縮放及開啟完整圖。整圖縮圖只作概覽，不算閱讀檢查通過。
- **密度控制。** 卡片只承載一個任務或一組共同準則。通常超過約十張卡、三條長距離回線或需不斷左右找線時，先重新分段；這是設計提示，不是醫學規則或工具硬限制。
- **中文與數值。** 中文依可用寬度換行；藥名、數字＋單位、比較符號附近逐項檢查。不能裁掉否定詞、註腳、百分比基準或「目標量」等劑量性質。
- **留白與對齊。** 等距內邊、同層卡片對齊，分支標籤有白底且不蓋住線路。節點大小隨內容調整，不能用同大空框或巨型菱形填滿版面。

## 5. 實作規格

`config/flows/<id>.yml` 是唯一圖文定義；欄位見 [schema](schema.md)。`presentation: clinical-cards` 使用臨床卡片；既有沒有此欄位的流程使用 Pele。`items` 為可見純文字小項，`role` 為視覺用途，`kind` 仍表達圖結構。`card_width` 可在320–720之間依內容調整；它不修改規則。

每個箭頭列 `from`、`to`、`label`，需要時設 `role: option` 或 `role: feedback`。未知節點只有在明示補資料／重評的 feedback 箭頭才可再出發；terminal 不可再出發。未知出口需要實際缺漏／核對項目，不是只寫「請諮詢」。

SVG 僅用安全原生向量／文字，無外部程式、遠端圖或 foreignObject。定義、排版程式、固定套件及成品雜湊保存於 manifest；公開 clone 可用已驗證成品建置，重新排版才需安裝 Node 套件。Mermaid 匯出與網站文字版也保留卡片項目，不另外手寫一套摘要。

```powershell
npm ci --prefix tools/diagrams --ignore-scripts
python scripts/flows.py --build
python scripts/flows.py
python scripts/build_site.py
python scripts/lint.py
python -m unittest discover -s tests -v
```

## 6. 驗收需留下的證據

| 層次 | 必查項目 | 完成依據 |
| --- | --- | --- |
| 來源 | 版本、族群、所有數值／條件、表圖註腳、建議語氣、衝突 | 定位及來源審查紀錄 |
| 路徑 | 真／假／未知、重疊、邊界、例外、安全優先、可執行動作、後續 | 從來源先寫的虛構教學案例走查，不是病人結果 |
| 圖形 | 完整字串、無遮擋／越界、可追箭頭、層級與留白、原尺寸閱讀 | 實際 SVG 渲染檢視，非僅 XML 合法 |
| 工程 | 安全轉義、定義驗證、圖文一致、雜湊、確定性、舊流程相容、公開邊界 | 適用測試、flow驗證、建置與lint |
| 介面 | 電腦／平板／手機、鍵盤、縮放、文字模式、無JS、列印 | 實際操作；無工具時明示未驗證，靜態PNG不代替瀏覽器驗收 |

本輪具體內容與驗收見 [redesign audit](clinical-flow-redesign-audit.md)。未審閱標示、缺口與衝突仍保留；不因圖更精緻就升級證據或審閱狀態。
