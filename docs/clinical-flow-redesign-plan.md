# Clinical flow redesign implementation plan

日期：2026-11-15。使用者已要求重畫、展示，並把臨床邏輯與視覺設計轉為可重複遵循的實作規範。

## 交付範圍

1. SJS：五項主準則合在一張卡，保留完整病程／鑑別的參與、三態資訊出口及補資料後回查。
2. MDD：將安全與再評估、治療策略、必要的逐藥安全內容分段；具體資料、時程、具名選項與限制直接可見。
3. 建置：YAML 是圖、文字版與 Mermaid 匯出的共同定義。既有 Pele 圖維持相容；新增臨床卡片呈現使用固定版本 ELK 排版與原生 SVG。
4. 規範：將前輪提案的已確認 SOP 納入 AGENTS，另建視覺製圖參考、決策表及驗收紀錄；不新增病人計算器或學習紀錄。

## 執行分工與順序

- 來源內容各由 SJS、MDD agent 處理，製圖程式獨立實作；根 agent 整合規範、閱讀介面及可見成品。
- 程式先以測試定義 rich-card、未知回饋、安全轉義、確定性及舊圖相容性，再實作。
- 內容、圖形與文字核對後實際渲染 SVG，檢視中文字、長句、分支標籤、交叉線、界限與留白，再調整。
- 完成後另請獨立 agent 審查臨床來源與工程實作，修正重要問題；Agent 審查不等同人工醫學審閱。

執行結果與未完成的裝置驗證見 [驗收紀錄](clinical-flow-redesign-audit.md)。

## 完成條件

- SJS ALL5 與未知／不符不混用，無4/5積分；MDD 暴露、量化、策略偏向及重評可走查，安全情境不等一般資料補齊。
- 門檻、單位、版本、藥物劑量性質及重要來源差異原樣保留；缺資料明示，不補造。
- 所有文字均在節點邊界內；主要卡片18px以上，不為整圖縮字；分支可追蹤，圖形與文字來自同一定義。
- 成品可無 JS 閱讀、下載 SVG；公開建置不含原件或 private，既有 URL 不變。
- 適用 Python／Node 測試、流程雜湊、索引、建置及 lint 通過；實際做過與未做的視覺／裝置驗證分別記錄。
