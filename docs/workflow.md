# 工作流程

## 處理來源

投放 → 原件歸檔/雜湊 → 書目與範圍 → 逐頁閱讀與圖表核對 → 來源摘要 → 更新相關 wiki/map → 引用/衝突標記 → 索引/log → 檢查。

個人經驗先驗證，再由使用者確認是否入庫；不能當一般來源自動寫成結論。指引與研究分歧並列 not_reviewed/open。外部醫學查證需使用者要求，預設不補找。

## 網頁內容與輸出

1. 知識正文寫入 wiki 或來源摘要，而非直接編輯產生的 HTML。
2. 經要求發布者設 `publish: true` 與英文 route。
3. 執行 `python scripts/build_site.py`，產生閱讀頁、首頁、公開搜尋資料與 wiki 索引。
4. 執行 `python scripts/lint.py` 及 unittest。
5. 本機開啟 index.html；GitHub 推送/部署另依授權進行。

手動成果不需 publish 欄位，放公開成果目錄即收錄。產生檔含 medwiki-generated 標記；工具遇到未帶此標記的同名手動 HTML 會拒絕覆寫。移除產生頁前先移除該 Markdown 的 publish 設定，再建置，舊 manifest 控制清理範圍。

## 前端互動

- 全站搜尋：Ctrl/Cmd K 或首頁搜尋；全文/別名，內容類型篩選。
- 閱讀：桌機三欄、平板雙欄加可展開目錄、手機閱讀區/返回/篇章抽屜。
- 引用：點 H/W 小標查看 DOI、PDF 頁與期刊頁。
- 表格：支援橫向捲動；鍵盤可聚焦。
- 文末：原文參考連結與前後篇章。
- 成果：已完成/待加入切換；沒有待加入的假連結。
- 不使用遠端字型、分析追蹤或即時 LLM API。

所有閱讀正文預先存在 HTML，搜尋與非必要互動依賴 JS。第一版無個案計算器、衛教稿、帳戶或同步書籤。

## 發布與備份

Pages artifact 僅使用 `.build/site`。公開摘要不代表有權公開原始全文或圖片。原始資料未入 Git，需另行備份；不要依賴清除建置資料來整理原件。
