# 工作流程

## 處理來源

投放 → 原件歸檔/雜湊 → 書目與範圍 → 逐頁閱讀與圖表核對 → 來源摘要 → 更新相關 wiki/map → 引用/衝突標記 → 索引/log → 檢查。

個人經驗先驗證，再由使用者確認是否入庫；不能當一般來源自動寫成結論。指引與研究分歧並列 not_reviewed/open。外部醫學查證需使用者要求，預設不補找。

新來源按疾病內容面向辨認新增、補強、修正、分歧及適用範圍差異，補進同一核心或既有章節；資料量及閱讀需要足夠才拆章。核心與章節共同檢視概念、流行病學、機轉、表現、診斷、鑑別與驗證、處置及限制，核心頁簡述目前範圍與重要缺口；來源 complete 不代表疾病總論已完整。同步核對導讀、回想答案、比較表、流程及缺口，不把各來源摘要拼成平行的疾病筆記。

## 網頁內容與輸出

1. 知識正文寫入 wiki 或來源摘要，而非直接編輯產生的 HTML。
2. 經要求發布者設 `publish: true` 與英文 route。
3. 執行 `python scripts/build_site.py`，產生閱讀頁、精簡首頁、科別／文獻／成果目錄、公開搜尋資料與 wiki 索引。
4. 執行 `python scripts/lint.py` 及 unittest。
5. 本機開啟 index.html；GitHub 推送/部署另依授權進行。

手動成果不需 publish 欄位，放公開成果目錄即收錄。產生檔含 medwiki-generated 標記；工具遇到未帶此標記的同名手動 HTML 會拒絕覆寫。移除產生頁前先移除該 Markdown 的 publish 設定，再建置，舊 manifest 控制清理範圍。

先宣告科別 map，再為頁設定 specialties。疾病核心發布時只列一個主要科別，所屬章節以 parent_id 明記關係並保持相同歸屬；歸屬不明先確認。其他科別的鑑別、共病或藥物安全論述用正文連結及 related_ids 指向既有疾病頁，不因此把該疾病／專題列入引用者科別。比較、思路及來源摘要等非疾病頁可依實際用途列多科。科別頁分四類目錄；只將真正主訴／跨科內容明記 cross_specialty。完整產生作品以 catalog_role: work 收錄，章節及來源摘要回到相關目錄。新增手動作品持續掃描，首頁只維持固定成果入口。閱讀返回需保留安全科別／圖譜脈絡。

學習內容以階層正文為本，複習問題先回想再揭示，答案附來源；需要對照時使用比較表，需要條件關係時使用經核對流程。不要求每頁套滿筆記方法，不另維護一套完整重複正文。無個人答案、進度或排程儲存。筆記版型不取代醫學來源與限制；目前工具不會自動理解醫學內容並修正衍生答案，須由 Agent 同步核對。

成功建置同步維護 `.gitignore` 的 MEDWIKI GENERATED OUTPUTS 區塊，只排除實際產生的 HTML 與搜尋 JSON，不排除整個成果資料夾。手動新增仍可追蹤；原件、可編輯來源及圖像資產的公開邊界不變。GitHub Actions 從公開來源重建成果；本機原件不參與發布建置。

## 臨床複習路徑製作

依 [AGENTS第8節](../AGENTS.md)、[製圖手冊](clinical-diagram-playbook.md)及[製作範本](../04_templates/clinical-diagram.md)完成八步：

1. 定義讀者的臨床旅程與種子情境，疾病複習預設接通診斷、嚴重度／分型、處置及反應後續。
2. 實讀原圖、相鄰正文、表格與註腳取得主幹；只有正文／表格時依資料依賴、處置先後及重評連接。
3. 建立臨床狀態—資料—條件—具體行動—重評—結果去向—來源定位表，列明內容缺口。
4. 以種子情境端到端走文字路徑，確認主要下一步與有內容的具名子圖銜接。
5. 刪除無作用框及重複狀態判斷；條件可標在線上，共同準則及並行工作合組，未知依當下行動需要處理。
6. 用直接醫學陳述取代多餘提醒；必要的適用條件、推薦強度、劑量性質、結果終點及分歧保留在建議旁。
7. 依臨床任務選圖及分區，先精簡內容與檢查密度，再調布局；主圖顯示主要條件與動作。
8. 先以來源預定答案驗只看圖的臨床複習及精簡前後一致性，再驗圖面、裝置與工程，分項記錄結果。

用途、版本、審閱狀態與通用說明在圖外集中一次。「參考正文」不代替完整路徑的下一步；未支持的操作細節記在製作紀錄，來源補查依既有授權。圖文定義保持單一來源，同步正文、答案、表格、資產、index與log。

## 前端互動

- 全站搜尋：Ctrl/Cmd K 或首頁搜尋；全文/別名，內容類型篩選。
- 閱讀：桌機三欄、平板雙欄加可展開目錄、手機閱讀區/返回/篇章抽屜。
- 引用：點 H/W 小標查看 DOI、PDF 頁與期刊頁。
- 表格：支援橫向捲動；鍵盤可聚焦。
- 文末：原文參考連結與前後篇章。
- 成果：已完成/待加入切換；沒有待加入的假連結。
- 不使用遠端字型、分析追蹤或即時 LLM API。

## 圖譜、共同頁與流程圖

1. 讀取提供的 HTML，原件、完整擷取與解碼留在 raw/private；公開來源紀錄保留版本與卡片/章節定位。
2. 先對照既有核心頁，合併同疾病階段及重複主題；來源摘要、科別 map、圖譜與思路入口連到同頁。
3. 圖片依位元組雜湊去重，分別保存每次圖說與使用情境；公開條件確認後才輸出原圖與資產紀錄，保留水印及全幅。
4. 流程先依上述八步完成臨床路徑及案例核對，再寫 config/flows 定義；呈現方式隨任務選擇，工程規格見[製圖手冊附錄](clinical-diagram-playbook.md)。
5. 首次產圖工具安裝：`npm ci --prefix tools/diagrams --ignore-scripts`。臨床卡片使用鎖定的 elkjs 0.12.1；既有圖使用 Pele 1.13.0。排版於建置時執行，不在讀者瀏覽器載入 CDN。
6. `python scripts/flows.py --build` 重建 SVG/Mermaid/manifest；實際渲染檢視中文、數值、分支、遮擋及留白，分別核對來源／案例／圖文，更新圖像資產紀錄後才執行網站建置。普通公開 clone 可使用已核對的 SVG 成品建置，無需本機原件。
7. 檢查同一主題跨入口 URL 一致、卡片定位、圖片/署名、圖譜篩選、自測揭示、流程縮放/節點/文字步驟與行動閱讀。自測不保存結果，不建立待讀或複習紀錄。

瀏覽器 URL 可保留當次篩選與返回位置，無帳戶、localStorage、IndexedDB、分析追蹤或同步資料庫。圖像與表格均保留可讀靜態內容；輕量動態遵守 reduced-motion。

完整維護紀錄仍在 log.md；正文不累積修訂列表。必要重大更正在頁尾收合，影響判讀的限制與衝突仍在相關內容旁顯示。

所有閱讀正文預先存在 HTML，搜尋與非必要互動依賴 JS。第一版無個案計算器、衛教稿、帳戶或同步書籤。

## 發布與備份

Pages artifact 僅使用 `.build/site`。公開摘要不代表有權公開原始全文或圖片。原始資料未入 Git，需另行備份；不要依賴清除建置資料來整理原件。
