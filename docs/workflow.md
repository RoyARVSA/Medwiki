# 工作流程

## 處理來源

投放 → 原件歸檔/雜湊 → 書目與範圍 → 逐頁閱讀與圖表核對 → 來源摘要 → 更新相關 wiki/map → 引用/衝突標記 → 索引/log → 檢查。

個人經驗先驗證，再由使用者確認是否入庫；不能當一般來源自動寫成結論。指引與研究分歧並列 not_reviewed/open。外部醫學查證需使用者要求，預設不補找。

## 網頁內容與輸出

1. 知識正文寫入 wiki 或來源摘要，而非直接編輯產生的 HTML。
2. 經要求發布者設 `publish: true` 與英文 route。
3. 執行 `python scripts/build_site.py`，產生閱讀頁、首頁、公開搜尋資料與 wiki 索引。
4. 執行 `python scripts/lint.py` 及 unittest。
5. 本機開啟 index.html；GitHub 推送/部署另依授權進行。

手動成果不需 publish 欄位，放公開成果目錄即收錄。產生檔含 medwiki-generated 標記；工具遇到未帶此標記的同名手動 HTML 會拒絕覆寫。移除產生頁前先移除該 Markdown 的 publish 設定，再建置，舊 manifest 控制清理範圍。

成功建置同步維護 `.gitignore` 的 MEDWIKI GENERATED OUTPUTS 區塊，只排除實際產生的 HTML 與搜尋 JSON，不排除整個成果資料夾。手動新增仍可追蹤；原件、可編輯來源及圖像資產的公開邊界不變。GitHub Actions 從公開來源重建成果；本機原件不參與發布建置。

## 前端互動

- 全站搜尋：Ctrl/Cmd K 或首頁搜尋；全文/別名，內容類型篩選。
- 閱讀：桌機三欄、平板雙欄加可展開目錄、手機閱讀區/返回/篇章抽屜。
- 引用：點 H/W 小標查看 DOI、PDF 頁與期刊頁。
- 表格：支援橫向捲動；鍵盤可聚焦。
- 文末：原文參考連結與前後篇章。
- 成果：已完成/待加入切換；沒有待加入的假連結。
- 不使用遠端字型、分析追蹤或即時 LLM API。

## 圖譜、共同頁與流程圖

1. 讀取提供的 HTML，原件、完整擷取與解碼留在 raw/private；公開來源紀錄保留版本與卡片/章節定位。
2. 先對照既有核心頁，合併同疾病階段及重複主題；來源摘要、科別 map、圖譜與思路入口連到同頁。
3. 圖片依位元組雜湊去重，分別保存每次圖說與使用情境；公開條件確認後才輸出原圖與資產紀錄，保留水印及全幅。
4. 流程先核對準則版本、全部/擇一條件、排除項、時間、數字/單位、未知與註解，再寫 config/flows 定義。
5. 首次產圖工具安裝：`npm ci --prefix tools/diagrams --ignore-scripts`。使用鎖定的 Pele 1.13.0，不在讀者瀏覽器載入 CDN。
6. `python scripts/flows.py --build` 重建 SVG/Mermaid/manifest；核對圖文、節點與引用，更新圖像資產紀錄後才執行網站建置。普通公開 clone 可使用已核對的 SVG 成品建置，無需本機原件。
7. 檢查同一主題跨入口 URL 一致、卡片定位、圖片/署名、圖譜篩選、自測揭示、流程縮放/節點/文字步驟與行動閱讀。自測不保存結果，不建立待讀或複習紀錄。

瀏覽器 URL 可保留當次篩選與返回位置，無帳戶、localStorage、IndexedDB、分析追蹤或同步資料庫。圖像與表格均保留可讀靜態內容；輕量動態遵守 reduced-motion。

完整維護紀錄仍在 log.md；正文不累積修訂列表。必要重大更正在頁尾收合，影響判讀的限制與衝突仍在相關內容旁顯示。

所有閱讀正文預先存在 HTML，搜尋與非必要互動依賴 JS。第一版無個案計算器、衛教稿、帳戶或同步書籤。

## 發布與備份

Pages artifact 僅使用 `.build/site`。公開摘要不代表有權公開原始全文或圖片。原始資料未入 Git，需另行備份；不要依賴清除建置資料來整理原件。
